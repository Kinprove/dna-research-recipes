# Working with 23andMe DNA: matches, matrices, segments, and preservation

## Goal

Turn a 23andMe account into a usable research packet: identified matches, a between-match
matrix, selected matching segments, and dated exports. Choose the next action from the
account's actual capabilities and each match's sharing permissions.

The expensive mistake is assuming that every visible DNA Relative can be compared in every
position, every percentage is autosomal-only, and every Download button returns the same
kind of evidence.

## Start with the account you actually have

Open the relevant profile and make a short capability sheet. Record the date, account/profile,
available tools, and any eligibility or sharing message shown on screen.

| Capability | What to check | Useful output |
| --- | --- | --- |
| DNA Relatives | Participation, available list and filters | Match identities and displayed amounts |
| Relatives in Common | Target's shared-match list and separate Shared DNA status | Between-match relationships and reported overlap |
| DNA Relatives Clustering | Availability, target selection, adjustable thresholds, Download | Numeric between-match matrix |
| Advanced DNA Comparison | Available primary profiles and permitted comparisons | Selected matching-segment rows |
| Data downloads | Raw DNA, relatives export, ancestry coordinates, other offered files | Separate dated artifacts |
| Parent information | Tested connected parents and available phasing features | Explicitly scoped side information |
| Family Tree / Reconstructed Ancestors | Placed DNA relatives, contributing relatives, and available ancestor profiles | Dated partial ancestry reconstruction |
| Optional browser extension | Enabled features and available account pages | Match/shared-match CSVs and group labels |

Check the vendor's current help and the account's eligibility message before paying for an
upgrade or planning a tool-dependent workflow. Subscription names, chip requirements,
regional availability, and match-list limits change. A missing button deserves an access
check; a withheld comparison belongs in the worksheet as **unavailable**. Participation and
ancestry sharing disclose different fields; record both. [O1]

Practitioners described a returned chromosome browser and newly introduced clustering in
2026; current official help describes both tools. Check access for this profile; help pages can retain
outage banners alongside feature documentation. A returned browser does not establish that
an all-match segment export also returned. [S1, S3, O2, O3]

Choose the output before choosing a tool: use recipes 1–3 for family leads and pairwise
amounts, recipe 4 for matching segments, recipe 5 for parent-side information, and recipes
6–7 for preservation and ancestry-coordinate handling, recipe 8 for filtering legacy segment
files with a known relative's list, recipe 9 for improving an ancestor reconstruction, and
recipe 10 for developer-documented extension exports and grouping, recipe 11 for a manual
shared-match chart, and recipe 12 for unconnected research-tree branches.

## Recipe 1: find a usable anchor and build a match worksheet

1. Start with a relative whose genealogical identity you already know. Open their profile and
   preserve the match identifier or stable profile link, displayed name, shared amount and
   unit, segment count if available, and provider-predicted relationship.
2. Add Family Background's ancestral surnames, locations, and external tree link. Record
   these as the match's reported information. Search the named branch with those clues;
   verify the person and descent in the tree before assigning your match to it. [S6]
3. Open Relatives in Common and record how much each useful match shares with the anchor as
   well as with you. Add an **identified relationship** column alongside the provider's
   prediction. The extra pairwise amounts often reveal a parent, child, sibling, or close
   cousin inside a group of otherwise distant matches. [S1, S5]
4. Use the available newest-relative or activity information to choose a contact who is
   likely to respond. Ask for a specific connection or a specific ancestry question.
   Record the request date and the permission still needed. [S1]

Make this a repeatable connection queue: inspect recently added matches, request the explicit
connection needed for the planned comparison, then use the Connections filter when available
to find accepted partners. For a genealogy question, ask for the relevant grandparents'
names, dates and places, their tree link, and whether they tested elsewhere. An active
person in the target's cluster can be a useful starting contact. [S1, S8]

Keep a searchable notes index outside the account. A 2023 practitioner account reports that
notes accompanied the relatives export. Inspect an existing CSV for that field; search it
locally by surname, place, branch or haplogroup. Where the field or export is absent, put
these clues directly in the worksheet, keyed to the match ID. A compact note such as
`branch=unknown; place=Tulchin; tree=URL; question=grandparents; evidence=reported` makes
later filtering practical without upgrading a reported clue into an identified ancestor.
The note format is synthesis; the historical export is not a current availability promise. [S7]

When one target does not respond, try an identified or active member of the same cluster.
Their cooperation can provide another route into the family. Their segment data establish
their own comparison; they do not supply the unavailable target's coordinates. [S1]

Suggested worksheet columns:

`profile | match ID/link | name | own amount/unit | anchor amount/unit | predicted relation |
identified relation | reported surnames/places | tree URL | sharing state | next question |
retrieval date`

## Recipe 2: use both rankings without mixing the quantities

Compare percentage ordering with strength-of-relationship ordering when they disagree.
The latter follows the provider's relationship prediction, which can incorporate segment
structure. These are different orderings, not interchangeable measurements. The dated 2022 practitioner example highlights
this particularly for endogamous match lists. [S4]

Before selecting a match by an autosomal cutoff or entering an amount into an autosomal
relationship calculator:

- Inspect whether the displayed amount includes X sharing. The 2022 account describes
  X-inclusive percentages and X-only matches with a different predicted relationship.
- Obtain the autosomal amount from available DNA details or segment rows when possible.
  Keep the X amount in a separate column.
- Preserve the original percentage and its scope. If the autosomal contribution is
  unavailable, mark it unavailable and choose a match with usable information.

Do not infer that strength-of-relationship sorting excludes X; neither the practitioner
account nor the checked official sorting help establishes that. Avoid transferring a historical universal percentage-to-cM cutoff into a current
analysis. Use the provider's labeled amounts and a calculator suited to the quantity you
actually have. [S4]

For close sibling comparisons, also retain the browser's half/full IBD distinction. Before
using a percentage or total in another calculator, check how both tools count fully identical
regions. The 2022 sibling article describes a historical 23andMe counting difference; do not
apply its conversion automatically to a current output. Preserve the original amount and
tracks instead of silently treating unlike totals as equivalent. [S9, O2]

The practical question is why this match changed rank, and whether its available evidence
helps the named branch. A provider prediction remains a prediction even when its ordering
is convenient. The current help defines the available sorts; check that definition rather
than reverse-engineering a biological relationship from the order. [O4]

## Recipe 3: turn a cluster into a numeric research matrix

Where clustering is available, begin with a known anchor or a target's Relatives in Common.
Record the selected target and all thresholds before generating the chart. [S1, S2]

1. Hover useful intersections to inspect the between-match amounts.
2. Download the cluster CSV and retain the original. Its cells describe pairwise sharing;
   they are not chromosome start/end coordinates.
3. Open the file in a spreadsheet. Check the row and column identities and a few displayed
   pair values against the account before using it to infer close relationships.
4. The February 2026 DNA Painter account describes pasting this CSV into a matrix through
   its **Load** menu. Verify that route in the current tool, then check imported labels and
   pair values. [S2]
5. Treat the controls separately: minimum/maximum sharing with you, minimum sharing between
   matches, and connection strength. Current official help gives an exploratory Leeds-style
   example of 50–70 cM minimum and 300–500 cM maximum with you. It describes connection strength
   1 as favoring mutually interconnected groups and 0 as maximally merging groups. Save the
   actual settings; these examples are not relationship or segment-validity thresholds. [O3]
6. If endogamy merges the chart into one broad group, raise the between-match minimum and
   keep your own match minimum at least as high. Official examples start at 30–50 cM and
   can exceed 100 cM in strongly endogamous cases. Compare changed membership against known
   anchors, including useful matches the filter removed; do not call the stricter chart
   the true family structure. [O3]
7. Save a second run with one deliberate setting change. Keep blanks, zeroes and omitted
   people as exported; do not relabel them as measured biological non-matches. A matrix
generated under different filters needs its own date and settings.

Use two runs for two different questions. A chart centered on you surveys the available
groups; a chart focused on one relative explores that target's shared-match cohort. Keep
the target selection with each matrix. If useful known cousins are absent, check the selected
cohort before assuming the branch disappeared. A February 2026 demonstration also varies
the number of included matches. Where that control is offered, vary it separately from DNA
thresholds and compare identities, not just colors. [S1, S2, S14]

Use the matrix to select the next identifiable person or willing comparison partner. A
cluster can guide branch research without naming the common ancestor or establishing a
same-segment group. Keep that attribution open until the required comparisons and family
identities are available.

## Recipe 4: get the segment comparison you can actually perform

Record three separate facts for each candidate:

- Is this person present in the shared-match list?
- What does the separate Shared DNA indicator report: Yes, No, or a withheld/unavailable state?
- Which numerical browser comparisons are permitted?

A Relatives in Common row records the shared-match connection. The separate **Yes** indicator
reports three-way overlapping DNA under the provider's definition. **No** does not rule out
a shared genealogical ancestor. A permission-limited result remains unavailable. The indicator
supports a segment hypothesis without identifying the ancestor; inspect the permitted pairwise
comparisons before assigning an interval. [O5]

The 2026 practitioner workflow distinguishes mutual Open Sharing from an explicit
connection. Open Sharing can expose a match's comparison with yourself. To make another
person the primary profile for a comparison with a third person, that primary profile must
be selectable as a managed or connected profile. Open Sharing to yourself alone does not
grant this selection. Check the primary-profile selector and record the missing permission
before requesting a connection. [S1, O2]

Where allowed, use the overlap's comparison link or **Compare with more relatives** to reach
Advanced DNA Comparison. Scroll to the numerical table and copy the selected rows into a
local spreadsheet. This route is described in the 2026 practitioner accounts. [S1, S3]

Preserve the focal profile, comparison partner, chromosome, start/end positions, cM, SNP count
if supplied, units, genome build if supplied, and retrieval date. Preserve half/full IBD
labels when supplied. Keep provider columns verbatim. If a field is absent, record that absence; do not manufacture it for an importer.
Retain the original copied table alongside any reshaped import file.

For a single match, DNA Painter's current help describes pasting the numerical comparison
table into **Paint a new match**. Preview it before saving: confirm the intended partner,
chromosome, endpoints and cM, and inspect which rows the importer accepts or filters. Keep
the original table so a failed or partial import can be retried without another account
visit. This gives a selected-match painting route when a bulk export is absent. [O10]

Add these rows to a known anchor-relative worksheet, with columns for which tested family
members share each match. Kitty Cooper describes this as a practical way to place new
matches against an existing family segment map. [S3]

For segment attribution and endogamous cluster interpretation, use
[ai-for-dna-research](ai-for-dna-research.md). For segment trust, X inheritance and phasing,
use [xdna-phasing-judgment](xdna-phasing-judgment.md). Relationship placement belongs to
[unknown-parentage-wato](unknown-parentage-wato.md); ancestor and identity rulings belong to
[evidence-proof-judgment](evidence-proof-judgment.md). Supply identified, permitted
comparisons to those methods.

## Recipe 5: distinguish DNA Relatives parent labels from ancestry-side inference

Classic DNA Relatives maternal/paternal filters depend on a tested, connected parent. Check
which parent is connected and what the label actually covers. A surname, ethnic similarity,
or shared haplogroup does not create that parent connection. This requirement is documented
for those DNA Relatives filters, not for every feature using a parent-side label. [O4]

For a "which side?" question, name the exact tool and output before interpreting its label.
Family Phasing / Parental Inheritance estimates ancestry-composition inheritance using
database relatives and can operate without a tested, connected parent. That is a different
output from the classic DNA Relatives Mom/Dad filters. Record whether a side assignment comes
from a connected parent, an inferred group, or an ancestry-composition model. Preserve unnamed
Parent 1 / Parent 2 labels until their identities are established; an inferred side does not
name the common ancestor. The current Premium Parental Inheritance page explicitly describes
Family Phasing without a connected parent; do not carry the older classic parent-based
phasing requirement into that different product. Record the feature name and inference
basis with the result. [O6]

To orient the generated Family Tree, start with an identified cousin or other documented
relative and check their placed branch. Do not assume that the left/right order names your
mother's and father's sides. The 2023 unknown-grandparent workflow combines these anchors,
tree placements and Relatives in Common. [S8]

Build a worklist with four grandparent columns plus **unassigned / multiple lines**. Record
the documentary anchor, provider placement and RIC links separately for each match. When
three grandparent lines are known, investigate a residual group as a candidate fourth-line
lead; lack of links to those anchors does not assign it automatically. Ask the candidate
family for a tree and grandparents' details, then test that lead with the relationship and
evidence recipes. This worklist is synthesis of the source's method.

Use the haplogroup shown in a profile as a bounded search clue. For incompatible calls,
direct-line exclusions, and choosing a more informative test, use
[ydna-mtdna-interpretation](ydna-mtdna-interpretation.md).

## Recipe 6: preserve the five different data products

| Artifact | What it preserves | Practical handling |
| --- | --- | --- |
| Raw genotype file | Tested marker calls | Request separately; allow for processing and email delivery |
| Relatives/match CSV, when offered | The exported match fields at that date | Save the original and inspect its actual columns |
| Cluster matrix CSV | Between-match amounts for selected settings | Save target, thresholds, labels, and date |
| Selected segment table | Coordinates for permitted comparisons | Save focal person, partners, units, and supplied build |
| Ancestry Composition coordinates | Population assignments along chromosomes | Save confidence setting and date |

A raw genotype download does not preserve your match identities or private conversations.
A matrix CSV does not preserve matching-segment coordinates. Ancestry Composition coordinates
describe ancestry assignments; they do not establish a match's shared segment. [S1, S3, S5]

Request raw data early if preservation matters. Processing may take days; confirm the email
address and retain the request confirmation. Follow the current delivery instructions rather
than promising an immediate download. This is a separate genotype request, not a backup of
DNA Relatives. [O8]

Preserve profile clues, external tree links, useful communications, and the match worksheet
alongside exported files. Start with the closest identified matches and the branch relevant
to the research question. [S5]

Keep pre-breach relatives exports and older cluster outputs as dated originals. Add a new
snapshot instead of overwriting them. A missing person in today's displayed list may reflect
participation, access, or list limits; inspect those conditions before using the absence in
an analysis. The 2024 preservation article describes an outage-era workflow and historical
exports, not the current feature set. [S5, S6]

Keep the untouched 23andMe genotype file before any transfer or format conversion, and
preserve transformed copies separately. Check the destination's current acceptance page
for the original chip/file version and live upload availability. A destination's usable
marker set and downloadable output need not reproduce the source file. Transfer advice in
an old tutorial is a lead to verify, not a standing list of working destinations.
For example, MyHeritage's current official help says it no longer accepts DNA uploads;
an older instruction to upload 23andMe there is obsolete. [O13]

## Recipe 7: preserve ancestry painting without turning it into matching evidence

When the question concerns an ancestry assignment, use Ancestry Composition's chromosome
painting and confidence controls rather than a match-segment table.

1. Record the selected confidence threshold and save the ancestry-coordinate export.
   Current official help specifies NCBI Build 37 for this CSV; keep that build with these
   rows without assuming it establishes the build of a different export. [O7]
2. Compare a second supported confidence setting and retain both outputs. Record which
   assignments persist, broaden or disappear; a changing assignment does not document a
   particular ancestor.
3. Keep these rows labeled as population assignments when painting or importing them.
   They are not pairwise IBD coordinates and cannot substitute for a missing match table.
4. If two matching intervals show different ancestry labels, do not reject the DNA match
   from the colors alone. Official help explains that Ancestry Composition and DNA Relatives
   use different phasing treatments. Check the actual matching evidence separately. [O7]

Inspect population categories before summarizing imported rows. One 2022 DNA Painter example
found both a broad population and its narrower child population in the same 23andMe export.
Keep the original rows and choose a consistent category level for a summary; do not add
nested labels as if they were independent tracts. Record that filtering choice. [S11]

Keep ancestry overlays in a clearly labeled map or layer, separate from a map of identified
matching relatives. Painting both can help explore an interval, but a matching color is not
an ancestor identification. Check the imported intervals and the original confidence
setting before drawing conclusions from an imported overlay.

The 2022 population-painting tutorial uses the chromosome map's settings menu and
**Import 23andme ancestry composition** to paste its CSV. Use the dedicated population
importer in a separate map and check the imported rows. The same tutorial warns
that Copy 1 / Copy 2 can change parental meaning across chromosomes without identified-parent
phasing. Save those labels verbatim and check the present export's phasing basis; do not
rename Copy 1 globally as Mom from one chromosome. This is a dated export lesson, not a
requirement that every current phasing feature have a tested parent. [S13]

For a changed ancestry result, open the available **Version History**, compare the new and
previous outputs, and read its **Change Log**. Record both version labels and confidence
settings. The September 2025 version-7 announcement limits that release to V5 customers
with ancestry-service access and gives Premium members a broader previous-version/confidence
history. Compare what this account offers; an algorithm update changes the estimate rather
than documenting a newly inherited ancestor. [S18, O18]

For a recent geographic lead, open the Country Match or Genetic Group and save its displayed
confidence label. Inspect a Country Match's available shaded subregions: darker shading
reflects more DNA-sharing participants reporting ancestors there, not a percentage of your
ancestry. Genetic Groups have no subregions; their outlines summarize reference individuals'
recent-ancestor birth locations and can cross national borders. Use the named places to
choose records and compare documented family locations, without assigning a particular
ancestor or parental side from this display alone. Current help gives inconsistent numeric
confidence bands, so retain the actual qualitative label. [S19, O19, O20]

## Recipe 8: bucket a legacy segment file with a known relative's list

An older all-match segment export can still support a new branch-focused worklist. DNA
Painter's Bucketing tool filters the main segment file by identifiers found in other files;
it does not require a tested parent. [S10]

1. Select your original segment CSV as the main file. Use the correct tester's file; a raw
   genotype download or clustering matrix is a different input.
2. Add an authorized match or segment file from an identified relative on the branch of
   interest. Use the same testing platform so identifiers correspond. Inspect a few known
   matches before filtering. Keep the source tester and file date with each input. [O9]
   If a full companion export is unavailable but the relative's matching IDs are available,
   the tool also accepts a minimal CSV whose first column is headed `BucketMatchID`. Use
   exact IDs from the same platform, not names or IDs copied from another vendor. [O9]
3. Choose inclusion or exclusion deliberately and record all size filters. Inclusion makes
   a branch candidate list. If using a parent's list for exclusion, label the remainder
   **not found in this parent's supplied list**; gaps in that list can remain.
4. Download the filtered CSV, retaining the originals. Inspect it in a spreadsheet or import
   it into a separate DNA Painter map/group for follow-up. [S10, O9]

These buckets use match-list membership, which can include different relationship paths.
They do not establish pairwise matching on the same interval or assign every segment to the
known relative's branch. Inspect useful matches with recipe 4 and the existing DNA judgment
recipes, especially in endogamous families.

## Recipe 9: improve a Reconstructed Ancestor through verified tree placements

Where the feature is available, use it to explore an ancestor's partial ancestry profile.
It depends on DNA relatives placed in the Family Tree. The October 2025 tutorial demonstrated
an early beta; the March 2026 official launch describes parents and grandparents. Check
current eligibility rather than copying the tutorial's beta-enrollment requirement. [S12, O11]

1. Save the ancestor label, displayed reconstructed amount/completeness, available ancestry
   view and listed contributing relatives before changing the tree.
2. Verify the identity and descent of a useful DNA Relative. Check their current placement
   and relevant alternate paths before adding or correcting their position. Attach the
   actual DNA Relative to the right tree person; merely typing an ancestor's name supplies
   no additional tested DNA. [S12]
3. Revisit the profile after the tool updates. Save the date, placed relative and changed
   output. The vendor says additional placed relatives can make a profile more complete;
   a change is not guaranteed for every added person. [O11]
4. Inspect contributing relatives where that view is offered. Resolve misplaced donors
   before using the ancestor's population breakdown in further research. [S12]

Tree placement is an input. Do not move an uncertain relative between candidate brothers
and treat a fuller reconstruction as proof of which brother was the ancestor. Endogamy and
multiple paths can also impair attribution. Preserve the result as a partial model, separate
from your documentary tree and independently tested relationship hypothesis. [S12, O12]

## Recipe 10: export and group visible matches with Genealogy Assistant

The April 2026 visual-tagging article points to Genealogy Assistant for 23andMe shared-match
groups. Its developer separately documents match-list and shared-match CSV downloads.
These are extension operations, distinct from a native 23andMe export. Check the extension's
current installation, license and feature settings before relying on them. No extension was
installed or used on a private account for this recipe. [S15, O14, O15]

1. Enable **23andMe Download Matches Pages as CSV File** in the extension panel and open
   DNA Relatives. Set a page count or leave it empty for all pages in the accessible list.
   Download the CSV and retain tester, retrieval date and chosen scope. Developer-documented
   columns include shared amounts, segment count, predicted relationship, star status,
   Groups, Match GUID and Match URL. Check several IDs and amounts against visible rows. [O14]
2. For a particular anchor, enable **23andMe Download Shared Matches as CSV File** and open
   that match's Relatives in Common. Choose the page scope and download. The documented CSV
   separates your shared amounts from **Shared cM with Match** and **Shared Percentage with
   Match**, retaining URLs and GUIDs. Use those labeled quantities to populate the anchor
   worksheet rather than transcribing each between-match value. Record the focal tester
   and anchor with the file. [O15]
3. To label that cohort, enable **23andMe Add Groups to Shared Matches**, open **Add/Manage
   Groups**, and create the intended group. Select individual matches or use **Select across
   all pages** for the shared list, then assign the selection to that group. The developer
   describes per-kit assignments that persist across sessions. Save the cohort scope and
   export its Groups field for your local index. [O16]
4. Use a consistent color/name scheme across platforms, as the practitioner article proposes.
   Keep a candidate-branch label distinct from a documented relationship. A structured name
   such as `branch=Tulchin | status=candidate` is our synthesis. Join 23andMe snapshots using
   sample-checked 23andMe IDs; use an explicit verified mapping for another provider's IDs.
   A group label alone does not assign every member to an ancestor. [S15]

For quick relationship-range exploration, the extension also offers a **DNA Painter Shared
cM Tool** button on a match profile. Its developer explicitly says it converts the displayed
percentage to cM before opening the calculator. Keep that conversion separate from directly
reported amounts. The CSV help pages do not specify the origin of their cM fields: preserve
their percentages and label the cM fields as extension-produced rather than assuming measured
autosomal-only totals. Use recipe 2 when selecting calculator inputs. [O14, O15, O17]

These exports collect the accessible match pages described by the developer. They do not
establish matching-segment endpoints or restore a native bulk segment download. Keep each
export as a dated snapshot and preserve the original column names. Current documentation
was checked; actual account/browser behavior remains untested.

## Recipe 11: build a manual Leeds worklist from Relatives in Common

When native Clustering is unavailable but Relatives in Common is accessible, organize the
visible matches in a manual color chart. The March 2022 tutorial demonstrates spreadsheet
seed iteration; its former bulk-download route and fixed percentage conversions are dated
examples. Start with the quantities and access checks in recipes 1–2. [S16]

1. Make one row per selected match with its stable ID/link, displayed amount/unit, predicted
   and identified relationships, and retrieval date. Choose the cohort for your branch
   question. Known second cousins can help seed a grandparent-line exploration; keep
   descendants and closer family as separate anchors because they can span several lines.
2. Give the first eligible uncolored seed a column/color and record which person started it.
   Open that seed's Relatives in Common. Color people present in both that list and your
   selected cohort. Keep the source list or retrieval date with the run.
3. Repeat with the next eligible uncolored person until the cohort has been examined. If a
   person appears in several seed lists, preserve every membership. Mark a withheld or
   unexamined list as unavailable rather than recording an empty group.
4. Research the groups using documentary anchors. If a seed joins a broad set, save a
   separate run from a documented alternative seed and compare the additional people. The
   tutorial suggests trying a known second cousin and then a stronger match in that group. Preserve
   both seed identities and runs. [S16]

Overlapping colors record shared-list membership. They do not identify a matching interval
or establish segment triangulation. Four colors alone do not identify four grandparents.
Use the chart to select family research or a permitted comparison with recipe 4. Extension
groups can store labels where available, alongside the local chart and seed record.

## Recipe 12: carry a match into an unconnected research-tree branch

An external research tree can hold an identified match's family while their relationship to
the tester remains unresolved. A 2021 Family Locket tutorial demonstrates private Ancestry
trees, floating branches, custom tags and person notes. Use a tree tool that supports
unconnected people and check its present controls. [S17]

1. Create a research tree and choose its privacy/searchability settings. The tutorial's
   unknown-parentage project uses a private, unsearchable tree. Record the focal tester and
   research purpose.
2. Add a useful 23andMe match as an unconnected person or floating branch. Use the tool's
   supported creation route and verify that no unsupported parent/child connection remains.
   The dated demonstration adds a new person from a record or temporarily connects a person
   and then removes only that connecting relationship.
3. Tag the person with provider and focal tester. Retain their match ID/link, amount/unit,
   predicted relationship, available X status and haplogroups, reported surnames/places,
   and useful Relatives in Common in dated notes beside the source observations. [S17]
4. Research their parents and grandparents from records and tree leads. Add other useful
   matches as separate branches and compare documented ancestors. Join a branch when the
   identity and relationship have support; keep competing placements separate.

Keep haplogroups in labeled notes or research fields rather than using them as parent names.
A shared haplogroup or X match alone does not identify a mother. This external tree remains
separate from generated 23andMe placements and reconstruction inputs in recipes 5 and 9.

## Prompt patterns

These are original workflow prompts; supply the worksheet and files they request.

### Choose the next workable comparison

> Given this 23andMe capability sheet, target profile, and sharing states, list the
> comparisons I can perform now. For each blocked comparison, identify the missing
> permission or data field and a concrete next action. Keep unavailable results explicit.

### Read a numeric matrix

> Validate these cluster CSV identities and sample pair values against the supplied checks.
> Rank three useful follow-up matches for researching [named branch]. Explain the choice
> using between-match amounts, verified identities, activity, and available permissions.
> Keep cluster membership separate from segment coordinates and ancestor attribution.

### Prepare a segment import

> Reshape these copied segment rows for [tool]. Preserve the original columns and retain
> focal profile, partner, chromosome, endpoints, units, supplied build, and retrieval date.
> Report any missing required field before creating an import-ready table.

### Audit the preservation packet

> Inventory these files by artifact type: raw genotypes, relatives export, cluster matrix,
> selected matching segments, and ancestry assignments. Identify which match identities,
> settings, permissions, dates, and communications still need a local record.

### Make a branch worklist from archived files

> Given these dated 23andMe segment and match files, identify compatible inputs for a
> known-relative bucket. Preserve the source IDs, tester and date. State the inclusion or
> exclusion rule, validate sample IDs, and label what the resulting membership can establish.

### Audit reconstruction inputs

> Given this Family Tree placement list and the ancestor profile's contributing relatives,
> identify which placements are documented and which depend on a hypothesis. Propose a
> useful verified addition and the before/after fields to save. Keep the reconstruction
> output separate from evidence used to establish the relationship.
